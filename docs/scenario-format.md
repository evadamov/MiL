# Формат сценария

Версия формата 1. Часть платформы MiL ([spec.md](spec.md), п. 0): здесь —
как устроен файл, который приложение показывает, а движок считает. Механики,
на которые ссылается сценарий, описаны в [mechanics.md](mechanics.md).

Сценарий — это Markdown в репозитории. Его пишет человек или ИИ вне
приложения. Приложение читает его без ИИ: проза становится текстом слайдов
и экранов команд, структурированные блоки — моделью шагов. Любое отступление
от формата — ошибка с указанием файла, строки и столбца.

Примеры: [scenarios/lemonade/](../scenarios/lemonade/scenario.md) —
два сезона, 20 шагов; [scenarios/rink_tea/](../scenarios/rink_tea/scenario.md)
— один файл, одна фаза, одно и то же решение каждый шаг.

Первая версия формата сознательно узкая: только воркшоп с ведущим, шаги
идут по порядку, событий нет. Что отложено — п. 12.

---

## 1. Файлы

```
scenarios/
  <scenario-id>/
    scenario.md        входной файл: фронтматтер, корневой блок, справка, выводы, проверки
    <любое>.md         подключается, только если указан в include
    assets/            картинки слайдов
    canon/             исходные материалы; приложение их не читает
```

Сценарием считается каталог, в котором есть `scenario.md`. Другие `.md`
компилируются только через `include`, поэтому в каталоге можно держать
черновики и канон.

Порядок чтения: `scenario.md`, затем файлы из `include` в указанном порядке.
Шаги идут в порядке этой склейки.

Кодировка UTF-8, переводы строк LF или CRLF. Строки и столбцы в ошибках
считаются от 1 в исходном файле.

## 2. Фронтматтер

Только в `scenario.md`, строго первым блоком, YAML.

```yaml
---
id: lemonade                  # совпадает с именем каталога
version: 17                   # целое, растёт при каждом изменении смысла
title: Малыш и лимонад
locale: ru
duration_min: 90              # бюджет времени
format: 1                     # версия этого документа
library: 1                    # мажорная версия библиотеки механик
teams: {min: 3, max: 10, recommended: [5, 9]}
include: [season-1-yard.md, season-2-park.md]
---
```

Все поля, кроме `include` и `teams`, обязательны. Неизвестное поле —
ошибка `E002`, а не молчаливое игнорирование.

## 3. Разметка

### 3.1 Заголовки — это директивы

Заголовок задаёт вид раздела, идентификатор и название. Разделитель
названия — ` · ` (пробел, U+00B7, пробел); делится по первому вхождению.

```
# phase <id> · <название>        фаза (сезон, этап) — группа шагов
## step <id> · <название>         шаг внутри фазы
### <слот> [(if <условие>)]        текстовый слот шага или фазы

# info                             справка для команд
## page <id> · <название>

# lessons                          выводы
## lesson <id> · <название>

# checks                           эталонные проверки
## check <id> · <название>
```

- `id` — `^[a-z][a-z0-9_]*$`, уникален внутри своего вида; идентификаторы
  шагов уникальны во всём сценарии.
- Уровни не перескакивают: `##` внутри `#`, `###` внутри `##` или `# phase`.
- Заголовок, не подходящий ни под одну форму, — ошибка `E010` с подсказкой
  ближайшей формы. Заголовки для оформления текста внутри слота — уровень 4
  и ниже.

### 3.2 Блок модели

Структура раздела задаётся одним fenced-блоком с меткой `sim`:

````markdown
## step d9 · Вторник · Цена колы

Текст вводной.

```sim
duration: {min: 2, max: 3}
inputs: [...]
mechanics: [...]
```
````

- В разделе не больше одного блока `sim`. Блок вне директивы допустим один
  раз — в `scenario.md` до первого заголовка: это корневой блок (п. 4).
- Блоки с другими метками (` ```text `) — часть текста.
- Содержимое — YAML 1.2, core schema. Запрещены якоря, ссылки, теги,
  merge-ключи и несколько документов в блоке; дубликат ключа — ошибка.
  JSON — подмножество YAML, поэтому JSON-блок тоже корректен.
- У каждого вида раздела своя JSON Schema с `additionalProperties: false`.
  Ошибка схемы указывает на строку ключа.

### 3.3 Текст и слоты

Шаг проходит фазы «вводная → приём ходов → результаты → вывод»
([spec.md](spec.md), п. 3). Текст для каждой фазы — свой слот. Текст шага
до первого `###` — **вводная**, остальное задают подзаголовки:

| Слот | Фаза | Где показывается | Если слота нет |
|---|---|---|---|
| (основной) | вводная | проектор и экран команды | слайд из одной картинки или пустой |
| `move` | приём ходов | проектор (рядом со счётчиком отправивших) и над формой у команды | остаётся вся вводная |
| `results` | результаты | над панелями, проектор и экран команды | только панели |
| `debrief` | вывод | проектор и экран команды | — |
| `discussion` | вывод | только проектор | — |
| `trainer` | все | только пульт | — |

`move` — та часть вводной, которая нужна, чтобы сделать ход: вопрос,
варианты, цены. Длинная легенда остаётся на слайде вводной, а во время
приёма в зале видно только задание.

Вывод бывает не на каждом шаге. Ведущий подводит итог раз в несколько
дней, поэтому фаза «вывод» есть только у шагов со слотом `debrief` или
`discussion`; у остальных после результатов сразу следующий шаг. Вывод может говорить о
нескольких прошлых днях сразу.

Условный вариант: `### results (if jug_bought)`. Условие — имя из
`conditions` шага или корня, допускается `!`. Показывается первый вариант,
чьё условие истинно; вариант без условия — запасной. Условие вычисляется
по снимку команды, поэтому разные команды могут увидеть разный текст. На
проекторе, где команд несколько, показывается вариант без условия.

Текст — Markdown: абзацы, списки, таблицы, выделение. HTML запрещён
(`E013`). Картинки в текст не вставляются: у слайда вводной одна картинка,
она задаётся в блоке (п. 5.2).

Подстановки — `{{путь}}` или `{{путь | формат}}`, путь — переменная из
п. 6 без `$`: `{{metrics.sold}}`, `{{at.d3.cash | money}}`. Форматы:
`int`, `money`, `percent`, `percent1`, `text`. Логики в подстановках нет.
Во вводной и в `move` видно только то, что известно до хода: параметры и
прошлые шаги; в `results` и `debrief` — ещё и снимок текущего шага.
Неизвестный путь — `E080`.

## 4. Корневой блок

Блок `sim` в `scenario.md` между фронтматтером и первым заголовком. Текст
рядом с ним — описание сценария в каталоге, который видит ведущий.

```yaml
currency: {label: монет, short: м}
params:                       # именованные константы, доступны как $p.<путь>
  yard: {price: 5, cup_cost: 2}
accounts:                     # подписи счетов на слайдах
  equipment: {label: Оборудование}
sources:                      # подписи источников движения денег
  dad_loan: Заём папы
conditions: {}                # общие именованные условия, как в шаге
reference: reference_team     # check, чьи решения — база таблиц вариантов
```

`params` — единственное место для чисел, которые встречаются больше одного
раза. Одно и то же число (кроме 0 и 1) литералом в параметрах механик двух
и более шагов — предупреждение `W030`.

## 5. Шаг

### 5.1 Блок шага

```yaml
duration: {min: 3, max: 4}    # минуты, обязательно
type: summary                 # только для итогов; остальные типы — по содержимому
legend: {image: assets/d2.png, layout: side}   # картинка вводной
inputs: [...]                 # поля хода
mechanics: [...]              # вызовы механик
results: {panels: [...]}      # состав слайда результатов
variants: [...]               # таблицы вариантов
tables: {...}                 # именованные таблицы для панели {table: <id>}
conditions: {...}             # условия для слотов и when
trainer: {checkpoint: "0:28", protected: true}
```

### 5.2 Вводная

```yaml
legend:
  image: assets/d2.png        # путь от каталога сценария
  layout: side                # side | full | text
```

| `layout` | Слайд вводной на проекторе |
|---|---|
| `side` (по умолчанию, если есть `image`) | картинка слева, текст вводной справа |
| `full` | картинка на весь слайд, текст — подписью внизу |
| `text` (по умолчанию без `image`) | только текст |

На экране команды картинка всегда над текстом. Файл должен существовать,
быть PNG, JPEG, WebP или SVG и не больше 2 МБ (`E014`). Внешние ссылки
запрещены.

### 5.3 Тип шага

Тип определяется по содержимому, кроме итогов:

| Тип | Признак | Слайд результатов по умолчанию |
|---|---|---|
| **Слайд** | нет ни `inputs`, ни `mechanics` | результатов нет: только вводная (и вывод, если есть) |
| **Автоход** | нет `inputs`, есть механики | `facts`, затем `variants`, если есть |
| **Ход** | есть поле `choice` или `number` | `choices`, `variants`, `facts` |
| **Расчёт / прогноз** | только `quiz` и `forecast` | `answers`, затем `facts`, если есть механики |
| **Итоги** | `type: summary` | `statements`, `teams`, `takeaways` |

Ход «на завтра» (вечерний заказ) — отдельный шаг-ход без механик; на его
поле ссылаются механики следующего шага.

### 5.4 Поля хода

```yaml
inputs:
  - id: jug
    type: choice
    label: Покупаем второй кувшин?
    options:
      - {value: buy, label: "Да, за 15"}
      - {value: skip, label: Нет}
    default: skip              # если команда не отправила
  - id: prep
    type: number
    label: Сколько стаканов заготовить?
    min: 0
    max: 80
    step: 1
    unit: стаканов
    samples: [15, 19, 25, 30, 40, 50]   # что перебирает проверка
    default: 30
  - id: breakeven
    type: quiz
    label: Сколько бутылок нужно продать, чтобы выйти в ноль?
    answer: 35
    tolerance: 0
    explain: "70 / 2 = 35"
  - id: forecast_days
    type: forecast
    label: Через сколько дней накопим?
    unit: дней
```

| Тип | Значение | Меняет модель | Особые поля |
|---|---|---|---|
| `choice` | одно из `options[].value` | да | `options`, `default` |
| `number` | число в `[min, max]` с шагом `step` | да | `samples`, `default`, `unit` |
| `quiz` | число | нет | `answer`, `tolerance`, `explain` |
| `forecast` | число | нет | `unit`; правильного ответа нет |

Для `choice` и `number` обязательны `default` (`E043`), для `number` —
`samples`. На `quiz` и `forecast` механики ссылаться не могут (`E044`).
Ход отправляется одной формой: все поля шага сразу.

### 5.5 Панели слайда результатов

`results.panels` заменяет состав по умолчанию:

```yaml
results:
  panels:
    - facts
    - {metrics: [{label: Маржа с бутылки, value: $metrics.unit_margin, format: money}]}
    - {table: horizon}
```

| Панель | Что показывает | Проектор | Команда |
|---|---|---|---|
| `facts` | воронка, экономика дня, деньги; только ненулевые строки | колонка на команду, или одна, если у всех одинаково | своё |
| `choices` | что выбрала каждая команда; для `choice` — сколько команд за каждый вариант | да | свой выбор |
| `answers` | ответы команд на `quiz` и `forecast`; правильный ответ и `explain` | да | свой ответ и правильный |
| `variants` или `{variants: <id>}` | таблица вариантов (п. 5.7) с отметкой выбора команд | да | да |
| `{metrics: [...]}` | список показателей `{label, value, format}` | по командам | своё |
| `{table: <id>}` | таблица из `tables` шага | эталонный путь | свой путь |
| `{statement: {kind, scope}}` | P&L, Cash Flow или Баланс; `scope`: `step`, `phase`, `game` | эталонный путь или выбранная на пульте команда | свой |
| `statements` | три отчёта за текущую фазу | так же | так же |
| `{teams: {columns: [...]}}` | «деньги команд»: строка на команду, колонки `{label, value, format}` | да | только своя строка |
| `takeaways` или `{takeaways: all}` | выводы текущей фазы или всей игры (п. 9) | да | да |

Ссылки в панелях вычисляются после снимка шага, поэтому в них доступен и
текущий шаг: `$at.<этот шаг>.…`.

`tables.<id>`: `rows` — ссылка на список; `columns` — `{label, value,
format}`, где `value` — поле строки (`profit`) или ссылка (`$...`).

### 5.6 Вызов механики

```yaml
mechanics:
  - use: funnel                # id из библиотеки
    id: lemonade               # имя экземпляра; по умолчанию = use
    when: jug_bought           # условие; механика пропускается, если ложно
    params:
      traffic: $p.park.traffic.fri
      conversion: 0.16
      price: $inputs.d11.lemon_price
```

Порядок исполнения задают стадии механик ([mechanics.md](mechanics.md),
п. 2), внутри стадии — порядок в файле. Параметры проверяются схемой
механики после подстановки значений, на каждом пути.

### 5.7 Таблица вариантов

```yaml
variants:
  - id: jug
    input: d2.jug               # шаг.поле; шаг — этот или более ранний
    values: options             # options | список значений
    columns:
      - {label: Прибыль к Д3, value: $at.d3.pl.cumulative, format: money}
      - {label: Деньги на Д3, value: $at.d3.cash, format: money}
```

Движок пересчитывает эталонный путь (`reference`), меняя одно решение, —
это замена «таблицы всех вариантов» на вкладке ведущего. В таблице
отмечено, какие команды что выбрали. Таблица ставится туда, где последствие
раскрывается, а не обязательно на шаг решения. `input` более позднего шага
— ошибка `E045`.

## 6. Значения и выражения

### 6.1 Ссылки

Строка, начинающаяся с `$`, — ссылка. Литерал с `$` в начале пишется `$$`.

| Ссылка | Что это |
|---|---|
| `$p.<путь>` | константа из `params` |
| `$input.<id>` | ход текущего шага |
| `$inputs.<шаг>.<id>` | ход любого прошлого шага |
| `$at.<шаг>.<путь>` | снимок прошлого шага (п. 6.3) |
| `$now.<путь>` | снимок текущего шага на этот момент; только в стадии `analysis` |
| `$metrics.<путь>` | метрики текущего шага; в панелях и тексте результатов |

Ссылка на шаг, который ещё не пройден, — `E041`.

### 6.2 Выражения

Значение, зависящее от ходов, — объект с единственным ключом `expr`,
внутри JSONLogic. Переменные — те же пространства имён без `$`.

```yaml
quantity: {expr: {"*": [{var: input.thermoses}, {var: p.thermos_cups}]}}
```

Явный ключ `expr` нужен, чтобы параметр-объект механики не спутался с
выражением. Платформа добавляет к JSONLogic три операции: `round`
(половина вверх), `argmax` и `argmin` (значение хода, при котором поле
строки максимально или минимально; для выводов-переборов).

Условие (`when`, `conditions`) — имя условия или `{expr: ...}`.

### 6.3 Снимок шага

После закрытия приёма движок фиксирует снимок по каждой команде. Его поля —
единственное, на что ссылаются текст, панели, выводы и проверки.

```
input.<id>                ходы шага
metrics.traffic …         торговый контекст: traffic, demand, sold, price,
                          conversion (продано / трафик), demand_conversion,
                          sold_cash, sold_credit, produced, waste_units, unit_margin
metrics.<экземпляр>.<…>   прочие метрики механик (collections, projection…)
pl.day                    прибыль шага
pl.phase                  прибыль фазы с начала по этот шаг
pl.cumulative             прибыль с начала игры
pl.lines.<счёт>           оборот P&L-счёта за шаг
cf.<источник>             движение денег за шаг по источнику
cash                      деньги на конец шага
balance.<счёт>            остаток счёта на конец шага, в естественном знаке:
                          активы, обязательства и капитал — положительные
check.balance             активы − обязательства − капитал; всегда 0
```

## 7. Порядок шагов

Шаги идут в порядке склейки, все команды проходят одни и те же шаги и
различаются только ходами. Ведущий может вернуться назад, чтобы показать
слайд ещё раз, но не может уйти вперёд, не раскрыв результаты текущего
шага: иначе у следующих шагов не будет данных.

## 8. Справка для команд

````markdown
| Параметр | Значение |
|---|---:|
| Цена стакана | {{p.yard.price}} |

```sim
from: d1                      # с какого шага видна; по умолчанию — с первого
```
````

Страница справки — Markdown с подстановками из `p.*`. Команда видит её в
разделе «Справка» с шага `from`.

## 9. Выводы

````markdown
# lessons

## lesson revenue_is_not_cash · Считать продажу деньгами

Отделять выручку от денег: у отсрочки есть срок, возвратность и сегмент.

```sim
phase: yard
takeaway: true
kind: contrast
contrast: {input: d2.jug, a: buy, b: skip}
assert:
  and:
    - {">": [{var: a.at.d3.pl.cumulative}, {var: b.at.d3.pl.cumulative}]}
    - {"<": [{var: a.at.d3.cash}, {var: b.at.d3.cash}]}
```
````

Заголовок — название ловушки, текст — «как избежать». Панель `takeaways`
собирает выводы фазы с `takeaway: true` в таблицу «ловушка — как избежать».
Отдельного текста выводов в сценарии нет, поэтому вывод и его проверка не
расходятся.

| `kind` | Что проверяется | Данные в `assert` |
|---|---|---|
| `path` | на каждом пути | `at.*`, `p.*` |
| `contrast` | на парах путей, различающихся одним решением | `a.*`, `b.*`, `p.*` |
| `sweep` | на каждом наборе прочих решений, по всем значениям хода | `rows[]` (у строки `value` и `at.*`), `p.*` |
| `unverified` | ничего; вывод без механической проверки | — |

`contrast`: `a` — значение или список; `quantifier: all | any` (по
умолчанию `all`) — для списка; `where` — условие над `a.*` и `b.*`,
которое отбирает пары.

Вывод `unverified` в отчёте проверки помечается как информация: видно,
какие выводы держатся на механике, а какие — только на словах ведущего.

## 10. Проверки

Проверка — эталонный прогон сценария с ожидаемыми числами. Это золотой
тест **этого сценария**: он описывает не поведение движка, а то, что
сценарий воспроизводит свой канон.

````markdown
## check reference_team · Референсная команда v16

```sim
decisions:
  d2.jug: buy
  d9.cola_price: 7
expect:
  at.d1.pl.day: 40
  at.d16.cash: 776
  at.d10.metrics.conversion: {approx: 0.121, tolerance: 0.0005}
```
````

```yaml
sweep:
  base: reference_team         # решения берутся из другой проверки
  input: d9.cola_price
  rows:
    - {value: 5, expect: {at.d9.metrics.sold: 17, at.d9.pl.day: -53}}
```

Не указанные решения берутся из `default`. Числа сравниваются точно, если
не задано `approx`. Проверка из `reference` обязана существовать и не
содержать `sweep`.

## 11. Ошибки

Формат сообщения одинаков для компилятора и проверки:

```
scenarios/lemonade/season-2-park.md:214:9  E031  step d13 › mechanics[1] (channel) › params.tiers[2].cost
  ожидалось целое число ≥ 0, получено "24 монеты"
```

Если ошибка зависит от ходов, к ней прикладываются ходы и числа:

```
scenarios/lemonade/scenario.md:31:1  E070  lesson revenue_is_not_cash › assert.and[1]
  ложно на паре: a = {d2.jug: buy, …}, b = {d2.jug: skip, …}
  a.at.d3.cash = 118, b.at.d3.cash = 115
```

| Код | Что |
|---|---|
| `E001`–`E002` | фронтматтер: нет, не YAML, неизвестное или отсутствующее поле |
| `E010`–`E011` | заголовок не по форме, неизвестный вид или неверная вложенность |
| `E012` | дубликат идентификатора |
| `E013` | HTML в тексте |
| `E014` | картинка: нет файла, не тот формат, больше 2 МБ, внешняя ссылка |
| `E020`–`E021` | блок `sim`: не YAML, запрещённая конструкция, не прошёл схему |
| `E030`–`E033` | механика: неизвестна, неверные параметры, две механики сбыта в шаге, спрос без сбыта |
| `E040`–`E045` | ссылки: неизвестная, на будущий шаг, —, нет `samples` или `default`, ссылка на `quiz`, вариант раньше решения |
| `E060` | бюджет времени превышен |
| `E061` | инвариант учёта нарушен (баланс не сходится, нецелые деньги) |
| `E070` | вывод не выполнен |
| `E071` | проверка не совпала с ожидаемым |
| `E080` | неизвестная переменная в подстановке |
| `W0xx` | предупреждения: повтор числа литералом, вывод без проверки, долг без шага возврата |

Сборка приложения падает на любой `E`. Предупреждения выводятся, но сборку
не останавливают.

## 12. Отложено

Не входит в первую версию. Формат оставляет под это место, нынешнее ломать
не придётся.

| Что | Как ляжет в формат |
|---|---|
| Соло-режим | слоты `debrief.solo`, варианты на пути игрока, раздел `# final` с итоговыми показателями и переигровкой |
| Ветвление сюжета | `next` — список `{if, to}`; ссылки на шаги не всех веток со значением по умолчанию |
| Случайные события | раздел `# events`: шаги, вероятность, эффекты на торговый контекст |
| Свои счета | `accounts: {<id>: {type, label}}` |
| Варианты одного сценария | несколько `scenario.md` с общими `include` и своими `params` |
